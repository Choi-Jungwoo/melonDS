# 从源码复刻新模拟器的实施路线

[返回总路由](README.md)。这是新实现的计划与完成标准，不声称本仓库已经完成下面所有测试。

## 先明确交付层级

用户要复刻整台模拟器时，终点包括 DS 核心、DSi 扩展、持久化、宿主输入输出和要求的联网/性能路径。下面各阶段只是让工作可验证，不能把“启动一个游戏”当作整机完成。

有两种可选择的实现边界：复用 melonDS core、重做平台/前端；或把设备逻辑移植/重新实现成新的核心。前者重点是 Platform 契约和生命周期，后者必须完成每个 CPU/设备状态机。本目录同时支持这两条路线；后续 agent 应在开始时记录自己采用哪种边界和目标平台。

## 建立最小、可对照的架构

建议以 `Machine` 持有全部客体状态，以 `Host` 提供外部效果；此处名称是设计建议，不是仓库 API。第一版用两个解释器和同步软件渲染，保持单个确定的模拟调度流；仅将音频播放、窗口和文件等宿主工作放到必要线程。

| 边界 | 输入 | 输出/副作用 |
|---|---|---|
| CPU step/run-until | 寄存器、总线、执行目标 | 新寄存器、周期、总线访问、异常 |
| Bus read/write | console/CPU/address/width/value | 数据或设备副作用、访问时间 |
| Device tick/event | 模拟时间、事件参数 | 状态、IRQ/DMA 请求、下次事件 |
| Machine run-frame | 已锁定的外部输入 | 实际行数、视频/声音、存储变化 |
| Snapshot | 当前机器与受控介质 | 可恢复状态，不含宿主地址 |
| Host | 文件/音视频/网络请求 | 明确的成功/失败和输入数据 |

先采用各模块已有的职责边界；不需要先造通用插件系统、通用总线 DSL 或可任意加载的设备图。枚举、定长数组、按地址分发足以建立第一版，而时钟、错误返回和设备容量不能省。

## 每个模块的交付包

模块完成时应留下以下六项，供下一位 agent 接续：

1. **状态**：客体寄存器、内部 latch/FIFO/计数、物理内存、复位值和不持久化的宿主缓存。
2. **输入出口**：MMIO 的 CPU/宽度/掩码、总线接口、事件、IRQ/DMA、宿主回调。
3. **转换**：每条事务的阶段、busy/ready/错误、结束条件与重入/取消行为。
4. **时间**：周期单位、首次/周期事件基准、CPU stall/追赶、相同时间事件顺序。
5. **恢复**：序列化字段、重建映射/指针、外部介质版本、线程同步。
6. **证据**：输入、参考输出、首个差异、通过范围，以及源码 TODO/未测范围。

这六项直接从主题文档的源码入口往下提取。仅提交寄存器名称列表或类图不满足设备可复刻要求。

## 完整性清单

- 指令：以 ARM/Thumb 分派表逐项覆盖；算术、移位、异常、PC 和访存边界都有独立输入。
- 总线：每 CPU/console/宽度/方向的已实现分支被覆盖；映射、空洞、权限、镜像明确。
- 事件：`Event_MAX` 所有事件归属明确；跨模块触发和取消有对应设备状态。
- 设备：Reset、MMIO、推进、IRQ/DMA、保存/恢复和宿主停止成闭环。
- 前端：新核心可在无界面模式固定输入重放，UI 只提供输入/显示/控制。
- 外部状态：ROM、BIOS、firmware、save、NAND、SD、Mic/Camera/网络输入来源可记录；读档的介质策略明确。
- 优化：每条加速路径可回到基准，缓存失效不改变行为。
- 范围：对照 [源码覆盖表](source-map.md) 无未归属的第一方功能；未完成 Netplay 等内容不冒充现成特性。

新 agent 接手先重放已记录的失败输入，再沿主路由补读模块；不重置已有的时钟/PC/字节序约定。新增设备或文件同步更新源码覆盖表和主题路由。
